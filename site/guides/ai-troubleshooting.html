AI attachment troubleshooting: a new tab is not an uploaded image

Updated September 13, 2026 · Based on the downloadable v0.3.6 package

CaptureAsk opens ChatGPT, Claude, Gemini or Grok and attempts to prepare an image attachment. Sign-in, upload availability and the provider’s interface can interrupt that handoff. Use the checks below to locate the failed step instead of repeatedly taking the same screenshot.

First identify what succeeded

  1. Was a screenshot created? Try Current tab and inspect the preview.
  2. Did the intended AI site open? Check the destination selected in CaptureAsk.
  3. Are you signed in and is the chat composer available?
  4. Does the composer show an image thumbnail or attachment indicator?
  5. Can you inspect that attachment before sending your message?

A visible AI home page proves only that navigation worked. It does not establish that the provider accepted the image. This guide does not claim successful uploads in all four services or account types.

Sign in before capturing

Open your chosen AI service and complete its normal sign-in flow first. Return to the source page and create a new capture. Version 0.3.6 marks pending image data with a two-minute expiry timestamp, so an old capture should not be relied on after a lengthy login or a page reload.

Use the same attachment check for all four services

For ChatGPT at chatgpt.com, Claude at claude.ai, Gemini at gemini.google.com and Grok at grok.com, verify that you are in an actual conversation composer that accepts images. Provider limits and controls can vary by account and interface. If an upload control is unavailable, CaptureAsk cannot grant that capability. Avoid sending repeated copies while the first upload is still processing.

Fallback: save, attach, verify

  1. Choose Current tab in CaptureAsk to create a preview.
  2. Use the download action. This version saves the preview to Chrome’s configured download location.
  3. Switch to the AI conversation and use that service’s file attachment control to choose the saved file.
  4. Wait for the thumbnail or upload completion indicator.
  5. Open or inspect the attachment where possible, type your question and send it yourself.

If copying succeeded, pasting into the composer may also work. Clipboard access and supported image formats vary, so the saved-file route is a useful alternative. There is no need to grant access to an unrelated website to attach a screenshot.

Large images and changed interfaces

The popup’s handoff in v0.3.6 skips storing an automatic attachment when its encoded data URL exceeds 7,000,000 characters. That is an implementation threshold, not a universal AI upload limit and not an exact file-size limit. Use a smaller area or save the file manually. The full-screen path already reduces the image to a maximum long edge of 1920 pixels.

An AI provider can change its input controls without an extension update. When the screenshot preview works but automatic attachment stops working on one provider, use manual upload and report the provider, extension version and failing step. Do not assume that opening a tab or focusing the text field confirms an attachment.

A better prompt after the upload

Explain the visible error. Quote the exact text you are using as evidence, list two likely causes, and give one non-destructive check for each. If any text is unreadable, ask me to provide it instead of guessing.

Compare the answer with the screenshot. Do not run commands or change account settings just because an AI suggested them. For a support report, describe the failure and include a redacted screenshot only when needed.

Implementation details were checked against the downloadable extension code. AI provider interfaces and account limits can change; automatic attachment is not guaranteed. Examples on this page are illustrative.
